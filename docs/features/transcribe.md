# Transcribe

How a user reaches it: the `transcribe` and `search_transcript` tools. `search_transcript` is hybrid by default (`mode: hybrid`); `mode: lexical` gives keyword matches only.

Code: `src/transcript/asr.py` (`transcribe_video`, `request_transcription`, `find_cached_transcript`, `_cached_result`, and the worker script inside `transcribe_video` that runs whisper.cpp for turbo or faster-whisper for tiny, base and small), `src/transcript/repeats.py` (`flag_repeated_segments`), `src/transcript/search.py` (`search_transcript`, `_fuse`), `src/transcript/semantic.py` (20 s chunks, cached vectors, the worker handle) and `src/transcript/eg2_worker.py` (the Core ML child process), `src/core/types.py` (`TranscriptSegment`, `TranscriptResult`, `SearchResult`).

How to check it works: `pytest tests/test_hybrid_transcript_e2e.py` (drives `search_transcript` through the MCP entry point on the fixture video; its model half skips unless the EmbeddingGemma 2 folder is set up) and `pytest tests/test_transcript_repeats.py tests/test_transcript_suspect.py tests/test_transcript_flag_wiring.py tests/test_asr_gate.py`. Live: run `transcribe` on a music video whose intro has no singing; the invented intro lines come back with `suspect`, and `notice` includes "Flagged N lines as suspect".

What depends on it: `search_transcript` (same transcript; passes `suspect` through to hits), `src/adapters/model_adapter.py` (rebuilds `SearchResult(**hit)`), and the background transcription job started from `src/executor/mcp_server.py`.

Gotchas:
- Turbo can invent lines over music or silence. Seen on a music video: "I don't know what to do." 14 times in a row over a 29 s intro, and "Thank you." over a quiet outro. Model confidence does not tell them apart (0.76 and 0.99, against 0.85 for real lyrics).
- A line that comes 3 or more times in a row (after lowercasing and dropping punctuation) gets `suspect` on every copy, and `notice` names the first run. A real chant gets flagged too; a lone invented line does not. A line without `suspect` is not verified.
- Flags are added each time a transcript is returned and are never stored: the cache keeps the unflagged transcript and its base notice, so transcripts cached before flags existed get them without re-running ASR. Subtitle sidecars are never flagged.
- whisper.cpp's voice check (Silero VAD, `--vad`) is off on purpose: on a music video it dropped 79-92% of the audio, including every sung line. The faster-whisper path (tiny, base, small) uses its own voice filter (`vad_filter=True`); it is untested on music and may drop sung lines too.
- A `.srt` or `.vtt` sidecar next to the video replaces ASR completely.

Hybrid search (`search_transcript`, default):
- Hits are labelled `match`: `exact` (the whole query appears as a contiguous run of words, or a single non-stop-word query term; pinned first), `all_terms` (every content term is in the line), `semantic` (a 20 s window, a guess by meaning). After the exact hits, keyword and semantic lists are merged by reciprocal-rank fusion (K=60); places within 20 s of a chosen hit are dropped.
- A `semantic` hit needs a cosine of at least 0.70 (`MIN_SCORE` in `src/transcript/semantic.py`). Below that, a query gets no semantic hit, and with no hit at all the `note` says no passage is close enough by meaning. Why 0.70: on `benchmarks/search_no_match` (a public bench-v1 clip, 2 h of dialogue; 50 queries about subjects not in the speech, 34 reworded lines; train = even list positions, held-out = odd), the best passage for an absent subject scored up to 0.76 and the passage for a reworded line 0.74 to 0.87. A cut of 0.74 (measured before the fix below, when the cut ran before fusion) gave the best train numbers (no-match queries with a semantic hit 2 of 25), but the repo's own paraphrase case (`tests/test_hybrid_transcript_e2e.py`, on `fixtures/synthetic_bench_60s`) scores 0.714 and lost its semantic hit, so 0.70 is the cut that keeps it. Derived, not a fresh Core ML run: the 0.70 cut is now applied after fusion, so the answer is the pre-cut answer (the 74eb3b3 baseline records) with semantic hits below 0.70 removed. Replayed on those records: no-match queries with any semantic hit went from 25 of 25 to 7 of 25 (train) and to 10 of 25 (test); reworded-line top-5 is 16 of 17 (train) and 14 of 17 (test). The records round scores to 3 decimals, and that rounding changes no count. The cut-before-fusion version gave the same counts on these queries but could push a keyword hit out of the answer (`test_semantic_cut_does_not_push_out_keyword_hits`). The test split was printed during the 0.70 tuning on 2026-10-30, so it is no longer untouched. The held-out gain is smaller than on train. A z-score gate over all passages (mean + 4 SD; measured before the fix, when the cut ran before fusion) dropped the reworded-line top-5 to 9 of 17 on train, so it is not used.
- A negative query can still return `semantic` hits. When no keyword hit exists, `note` says "No keyword match" and that semantic hits are the closest passages, not proof. Treat "nothing was said" as "no `exact` or `all_terms` hit", never as "no hits". Re-run `python benchmarks/search_no_match/score.py --source <local copy of the bench-v1 clip>` (Core ML environment set, see the setup below) after any change to the scoring; add `--final` only for a commit's final comparison.
- How to turn live hybrid search on (macOS with Core ML only; off until you do): (1) set `AGENTIC_VIDEO_EG2_DIR` to the folder holding `EmbeddingGemma2Text.mlpackage`, `embeddings.bf16`, `tokenizer.json`, `config.json`, or put that folder at the default path `~/.cache/agentic-video/models/embeddinggemma2-coreml`; (2) set `AGENTIC_VIDEO_EG2_PYTHON` to an interpreter that has `coremltools`, `tokenizers` and `numpy` (default: the server's own interpreter, which has none of them in the repo venv). Restart the server after changing either. If the model folder or the interpreter is missing or fails, `search_transcript` falls back to keyword hits only and the result carries a `note` saying why (for example "Semantic search is off (the EmbeddingGemma 2 Core ML model was not found in ...)"). Without the model, nothing else changes.
- The model runs in a child process on the Neural Engine (no GPU model is loaded), started on the first hybrid search, loaded once per process, and exited after 10 idle minutes (`AGENTIC_VIDEO_EG2_IDLE_SEC`, capped at 600) or when the server exits. The server never sends SIGKILL to the worker, because a killed worker leaves an `EmbeddingGemma2Text_<UUID>.mlmodelc` folder in the temp folder (Core ML releases it only on a normal exit). On shutdown the server closes the worker's input and waits 5 s, then sends SIGTERM (the worker handles it and exits normally) and waits 40 s more; a worker still busy after that is left to exit on its own when its input closes. On idle exit the server reaps the child at once (no zombie). The worker blocks `torch` and `tensorflow` imports (coremltools would load torch if it is installed). "Loaded once" covers the packed function that serves the chunks and every query up to 256 tokens. A query over 256 tokens loads a second Core ML function (`embed_512`) on its first use, which takes a while on a busy Mac. The search waits 30 s for a query vector, so on a busy Mac the first long query can fall back to keyword-only with a note; the load finishes in the worker and the next long query is fast.
- The worker's memory is highest while it indexes a long video; the server process stays small. The first search after a restart or idle exit pays the model load. A search waits up to 30 s for a missing index, then answers keyword-only with a "still building" note, and repeating the call joins the same build. A worker that dies is restarted once.
- Failures never cost the keyword answer: a missing or unrunnable `AGENTIC_VIDEO_EG2_PYTHON`, a dead worker, a bad reply or a failed index build come back as the keyword hits plus a `note` saying why. A missing interpreter or model is remembered until the server restarts, so fix the setting and restart.
- Chunk vectors are cached as `transcript_eg2.npz` next to the transcript cache, keyed by a hash of the model id, chunk settings and chunk texts, so a new transcript rebuilds them.
- The library `search_transcript(...)` and the engine stay keyword-only unless `hybrid=True`, so `model_adapter` and the ASR gate see the old result shape.
